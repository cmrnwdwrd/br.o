# BottleRag Player v28 — Refactor-only release

This release intentionally does not add or remove player features.

## Runtime structure

- `index.html` — page markup only
- `assets/styles.css` — all player styling, kept in the same cascade order as v27.1
- `js/01-core.js` — base metadata/API/rendering logic
- `js/02-player-ui.js` — audio transport, settings, category UI
- `js/03-history-storage.js` — IndexedDB, session/listening history, import/export
- `js/04-favorites-observed.js` — Spotify helpers, liked songs, observed-history ranking UI
- `js/05-shared-analytics.js` — GitHub shared history and Active Streams analytics
- `js/06-final-ui.js` — backup controls, simplified iPhone mode, search/filter/milestones, PWA registration
- `scripts/collect_bottlerag.py` — GitHub Actions data collector
- `.github/workflows/collect-bottlerag.yml` — scheduled collector workflow
- `data/` — shared generated history data

Observed BottleRag history is now split into two layers:

- `data/observed/YYYY-MM.json` — permanent monthly raw archives generated by the collector.
- `data/stats/observed_top50.json` — compact browser-facing all-time summary containing only the Top 50 Songs, Artists, and Albums.
- `data/stats/observed_aggregates.json` — collector-side cumulative counters used to update the compact summary efficiently.

The player no longer downloads or displays Recently Observed Tracks. It does not fetch monthly archive files during normal use.

On the first v29 collector run, an existing `data/observed_history.json` is migrated into monthly archives automatically. Preserve the existing `data/` directory when updating.

The Cloudflare Cron Trigger should invoke this workflow through `workflow_dispatch`; GitHub's native `schedule:` trigger is intentionally omitted.
